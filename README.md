# RentRoll · ระบบบริหารหอพัก

Next.js 15 (App Router) + TypeScript · PostgreSQL + Prisma 6 · Tailwind CSS 4 · shadcn/ui

## เริ่มใช้งาน (Windows / PowerShell)

ต้องมี **Node.js 20+** และ PostgreSQL สักที่ — จะเป็น **Docker Desktop** ในเครื่อง, PostgreSQL ที่ติดตั้งเอง หรือ **Supabase/คลาวด์** ก็ได้ (ดู [ใช้ฐานข้อมูลบนคลาวด์](#ใช้ฐานข้อมูลบนคลาวด์-supabase))

```powershell
cd D:\Project\dorm-manager

# 0) สร้างไฟล์ .env แล้วสุ่มค่า AUTH_SECRET, ENCRYPTION_KEY, CRON_SECRET (รันคำสั่งนี้ 3 ครั้ง)
copy .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

# 1) ฐานข้อมูล (ข้ามได้ถ้าใช้ Supabase/คลาวด์ หรือมี PostgreSQL อยู่แล้ว — แก้ DATABASE_URL ใน .env)
docker compose up -d

# 2) ติดตั้งแพ็กเกจ (จะรัน prisma generate ให้อัตโนมัติ)
npm install

# 3) สร้างตาราง + ข้อมูลตัวอย่าง
npx prisma migrate dev
npm run db:seed

# 4) รัน
npm run dev
```

เปิด http://localhost:3000

| บัญชี | ล็อกอิน | รหัสผ่าน |
|---|---|---|
| เจ้าของ | admin@gmail.com | pass123 |
| ช่าง | 1234567890 | pass123 |

> ตอนขึ้น production ให้สุ่ม `AUTH_SECRET` ใหม่และเปลี่ยนรหัสผ่านเริ่มต้น

## ใช้ฐานข้อมูลบนคลาวด์ (Supabase)

ไม่ต้องเปิด Docker — เอา connection string จาก Supabase Dashboard → **Connect** → แท็บ **ORMs** → **Prisma** แล้วใส่ทั้งสองบรรทัดใน `.env`

```
DATABASE_URL="postgresql://postgres.<ref>:<รหัส>@aws-0-<region>.pooler.supabase.com:6543/postgres?pgbouncer=true"
DIRECT_URL="postgresql://postgres.<ref>:<รหัส>@aws-0-<region>.pooler.supabase.com:5432/postgres"
```

ต้องมีสองบรรทัดเพราะ `DATABASE_URL` ต่อผ่าน **transaction pooler** (พอร์ต 6543) ซึ่งเร็วและรองรับการต่อพร้อมกันเยอะ แต่ใช้รัน migration ไม่ได้ — `prisma migrate` เลยใช้ `DIRECT_URL` (พอร์ต 5432) แทน ตั้งไว้ใน [schema.prisma](prisma/schema.prisma) แล้ว

สร้างตารางครั้งแรก (บนคลาวด์ใช้ `deploy` ไม่ใช่ `dev`):

```powershell
npx prisma migrate deploy
npm run db:seed
```

เลือก region ให้ใกล้ผู้ใช้ · ที่ใกล้ไทยที่สุดคือ `ap-southeast-1` (สิงคโปร์)
รองลงมา `ap-northeast-2` (โซล) และ `ap-northeast-1` (โตเกียว)

**เลือกแล้วต้องจำไว้** — ภูมิภาคของ Vercel ใน `vercel.json` ต้องตั้งให้ตรงกับที่นี่
ไม่งั้นทุก query จะวิ่งข้ามทวีปไปกลับ (ดูหัวข้อ deploy ด้านล่าง)

ตอนนี้โปรเจกต์ใช้ `ap-northeast-2` (โซล) คู่กับ Vercel `icn1`

## เอาขึ้นใช้งานจริง (Vercel)

ตราบใดที่ยังรันแค่ในเครื่อง ผู้เช่าเข้า `/t` ไม่ได้ · LINE ต่อไม่ได้ (webhook รับเฉพาะ https)
และ cron ออกบิลไม่ทำงาน เพราะเครื่องต้องเปิดค้างตลอด

**1. เตรียมรหัสฐานข้อมูล**

รหัสจะไปอยู่บน Vercel ด้วย ถ้ารหัสปัจจุบันเคยหลุดไปที่ไหน ให้รีเซ็ตก่อนที่
Supabase → Settings → Database → Reset database password แล้วแก้ `.env` ในเครื่องให้ตรงกัน

**2. เชื่อม repo กับ Vercel**

New Project → เลือก repo นี้ → Framework Next.js (ตรวจเจอเอง) → **ยังไม่กด Deploy** ใส่ตัวแปรก่อน

**3. ตัวแปรที่ต้องใส่ (Environment Variables)**

| ตัวแปร | ค่า | หมายเหตุ |
|---|---|---|
| `DATABASE_URL` | pooler พอร์ต **6543** ลงท้าย `?pgbouncer=true` | ตัวที่แอปใช้ตอนรัน |
| `DIRECT_URL` | pooler พอร์ต **5432** | ใช้ตอน migrate เท่านั้น |
| `AUTH_SECRET` | สุ่มใหม่ ไม่ต้องตรงกับในเครื่อง | เปลี่ยนแล้วทุกคนถูกพาไปล็อกอินใหม่ |
| `ENCRYPTION_KEY` | **ต้องเป็นค่าเดียวกับในเครื่อง** | คนละค่า = ถอดเลขบัตรประชาชนเดิมไม่ได้ |
| `CRON_SECRET` | สุ่มใหม่ | Vercel จะส่งเป็น `Authorization: Bearer <ค่านี้>` ให้เอง |

ไม่ต้องใส่ `SEED_*` บนเซิร์ฟเวอร์จริง มันใช้ตอน `npm run db:seed` เท่านั้น

สุ่มค่าใหม่: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

**4. กด Deploy**

`vercel.json` ตั้งไว้แล้วสองอย่าง
- `regions: ["icn1"]` — ให้เซิร์ฟเวอร์อยู่โซล ที่เดียวกับฐานข้อมูล (`ap-northeast-2`)
  ถ้าปล่อยเป็นค่าเริ่มต้น (สหรัฐฯ) ทุก query จะวิ่งข้ามมหาสมุทรไปกลับ หน้าเว็บจะอืดชัดเจน
  **ย้าย Supabase ไป region อื่นเมื่อไหร่ ต้องแก้ตรงนี้ด้วยเสมอ** — เทียบคู่: สิงคโปร์ `ap-southeast-1` ↔ `sin1` ·
  โซล `ap-northeast-2` ↔ `icn1` · โตเกียว `ap-northeast-1` ↔ `hnd1`
- `crons` — ยิง `/api/cron/billing` ทุกวัน 18:00 UTC = **01:00 น. เวลาไทย**

ส่วน `vercel-build` ใน package.json สั่ง `prisma migrate deploy` ก่อน build ทุกครั้ง
ตารางบนฐานจึงตามโค้ดเสมอ ไม่ต้องรัน migrate เอง

**5. ตรวจหลังขึ้น**

- เปิด `/login` เข้าด้วยบัญชีเจ้าของ
- เปิด `/t/login` จากมือถือ (ใช้เน็ตมือถือ ไม่ใช่ wifi บ้าน) เข้าด้วยรหัสผู้เช่า
- เปิดบิลสักใบแล้ว**สแกน QR พร้อมเพย์ด้วยแอปธนาคารจริง** ดูว่ายอดขึ้นตรงไหม
- ลองยิง cron ด้วยมือ: `curl -H "Authorization: Bearer <CRON_SECRET>" https://<โดเมน>/api/cron/billing`
  ควรได้ JSON กลับมา ไม่ใช่ `unauthorized`

## ทำแล้ว

**เฟส 1**
- ล็อกอินเจ้าของ/ช่าง (session cookie เซ็นด้วย JWT, middleware กันหน้า)
- ภาพรวม · ผังห้อง · จดมิเตอร์ (บันทึกทันที, คำนวณยอดสด, เก็บประวัติแก้ไข) · ตั้งค่า

**เฟส 2**
- **shadcn/ui** — `components.json` ตั้งค่าแล้ว เพิ่ม component ได้ด้วย `npx shadcn@latest add <ชื่อ>`
  ทุก component ใช้ `cn` จาก `@/lib/utils` และ primitive จากแพ็กเกจรวม `radix-ui` ตัวเดียว
  (ถ้า CLI รุ่นใหม่เติม `import { cn } from "cn"` มาให้ ต้องแก้กลับเป็น `@/lib/utils`)
- **ผู้เช่า & สัญญา** — รายการ/ค้นหา, ทำสัญญาใหม่ (ข้อมูลผู้เช่า, ค่าเช่า/ประกัน, ค่าบริการ, จดมิเตอร์ตั้งต้น), หน้ารายละเอียดห้อง, ย้ายออก (จดมิเตอร์วันออก + คืนประกัน), เปลี่ยนสถานะห้องว่าง/จอง/ปิดปรับปรุง · เลขบัตรประชาชนเข้ารหัส AES-256-GCM
- **บิล & ใบเสร็จ** — สร้าง/อัปเดตบิลร่างทั้งรอบ (ค่าเช่าคิดตามวันเมื่อเข้า/ออกกลางเดือน, ค่าซ่อมที่เรียกเก็บผู้เช่า), ส่งบิล, บันทึกรับเงิน (รับบางส่วนได้) + ออกใบเสร็จเลขรันต่อเนื่อง, คิดค่าปรับ, ยกเลิกบิล, หน้าพิมพ์ใบแจ้งหนี้/ใบเสร็จ A4 (บันทึกเป็น PDF จากหน้าต่างพิมพ์)
- **Cron รายวัน** `GET /api/cron/billing` (header `Authorization: Bearer <CRON_SECRET>`) — สร้างบิลร่างวันที่ตั้งไว้, ส่งบิลอัตโนมัติ (ถ้าเปิด), ปรับบิลเลยกำหนด + ค่าปรับ

ตั้งเวลาเรียก cron บน Windows (Task Scheduler) ด้วยคำสั่ง:

```powershell
curl.exe -H "Authorization: Bearer <CRON_SECRET>" http://localhost:3000/api/cron/billing
```

**เฟส 7 — เว็บฝั่งผู้เช่า**
- **`/t` สำหรับผู้เช่า** — ดูบิลและใบเสร็จ (มี QR พร้อมเพย์ระบุยอดให้เลย) · แจ้งซ่อมเองและตามสถานะ · ดูเลขน้ำ-ไฟย้อนหลังพร้อมค่าเฉลี่ย · อ่านประกาศ · ดูสาระสำคัญของสัญญา
- **ล็อกอินด้วยรหัส 8 ตัว + เบอร์โทร** ไม่ต้องตั้งรหัสผ่าน ไม่ต้องส่ง SMS (ไม่มีค่าใช้จ่ายต่อข้อความ) เจ้าของออกรหัสให้ที่หน้าห้อง `/rooms/[id]` · รหัสอย่างเดียวเข้าไม่ได้ ต้องคู่กับเบอร์ในสัญญา
- ผู้เช่าเห็นเฉพาะบิลที่ส่งแล้ว (บิลร่างของเจ้าของไม่โผล่) และเฉพาะของสัญญาตัวเอง
- หน้าเหล่านี้คือตัว LIFF ในอนาคต — พอต่อ LINE แล้วใช้ซ้ำได้เลย ไม่ต้องเขียนใหม่

**เฟส 6 — พัสดุ และการแยกข้อมูลระหว่างหอ**
- **พัสดุ** `/parcels` — รับฝากของ จ่ายของ (บันทึกชื่อคนที่มารับด้วย) ตีกลับผู้ส่ง · ค้นจากชื่อ เลขห้อง หรือเลขพัสดุ · เตือนของที่ค้างเกิน 7 วัน · กรอกจากมือถือหน้าเคาน์เตอร์ได้ พิมพ์เลขห้องแล้วกดบันทึกก็จบ
- **ปิดช่องโหว่ข้ามหอ** — หน้าภาพรวม ผู้เช่า งานซ่อม รายชื่อช่าง และหน้าห้อง เดิมดึงข้อมูลโดยไม่กรองหอ พอมีหอที่สองในฐานจะเห็นข้อมูลของกันและกัน
- **แจ้งเตือน LINE** `/settings/line` — ยังเป็นหน้าตัวอย่าง บอกว่าต้องเตรียมอะไร และโชว์ข้อความที่ระบบสร้างค้างไว้จริง ๆ ที่รอส่ง

**เฟส 4 — บัญชีและการสื่อสาร**
- **รายจ่าย** `/expenses` — บันทึกเงินที่หอจ่ายออก 8 หมวด (ค่าน้ำ-ไฟส่วนกลาง ค่าแรง ซ่อมบำรุง ภาษี ผ่อนธนาคาร ฯลฯ) แยกรายตึกได้ · หน้าภาพรวมคิดกำไร-ขาดทุนจากรายรับจริงลบรายจ่ายของเดือนเดียวกัน
- **รายงาน** `/reports` — สรุปรายเดือน (ออกบิล / เก็บได้ / ค้าง / รายจ่าย / กำไร) เลือกช่วงเองได้ และ**ส่งออก CSV 5 ชุด** (บิล · การรับชำระ · รายจ่าย · รายการในบิล · เลขมิเตอร์) ไฟล์ฝัง BOM ไว้แล้ว เปิดใน Excel ภาษาไทยไม่เพี้ยน
- **บอร์ดประกาศ** `/announcements` — เขียนประกาศถึงทุกตึกหรือเฉพาะตึก มีฉบับร่าง ปักหมุด และวันหมดอายุ (พอต่อ LINE แล้วส่งถึงผู้เช่าได้ทันที)
- **เตือนสัญญาใกล้หมด** — cron แจ้งเตือนสัญญาที่จะหมดภายในจำนวนวันที่ตั้งไว้ (สัญญาละครั้งเดียว) และมีแท็บ "ใกล้หมดอายุ" ในหน้าผู้เช่า

**เฟส 3 — แจ้งซ่อม**
- **ฝั่งเจ้าของ** `/maintenance` — รายการงาน (ค้างอยู่/เสร็จแล้ว/ยกเลิก) + ค้นหา, KPI งานแจ้งใหม่/กำลังซ่อม/งานด่วน/ค่าซ่อมรอเข้าบิล, เปิดงานใหม่ (ออกเลขที่ `MT-YYYYMM-NNNN` ให้เอง และผูกผู้เช่าปัจจุบันของห้องอัตโนมัติ), มอบหมาย/เปลี่ยนช่าง + วันนัด, ปิดงานพร้อมค่าใช้จ่าย, ยกเลิกงาน, ไทม์ไลน์ทุกการเปลี่ยนสถานะ
- **ฝั่งช่าง** `/tech` — มือถือเป็นหลัก: งานที่ได้รับมอบหมาย (งานด่วนขึ้นก่อน), กดเริ่มซ่อม, ปิดงาน + ใส่ค่าอะไหล่/ค่าแรง, โทรหาผู้เช่าจากหน้าจอ, งานที่ปิดไปใน 7 วัน
- **ค่าซ่อมเข้าบิล** — ติ๊ก "เรียกเก็บจากผู้เช่า" แล้วค่าซ่อมจะถูกดึงเข้าบิลรอบถัดไปเอง แก้ยอดได้จนกว่าบิลจะถูกส่ง · เรียกเก็บได้เฉพาะงานที่ผูกผู้เช่าไว้ กันค่าซ่อมของผู้เช่าคนก่อนไปโผล่ในบิลของผู้เช่ารายใหม่
- **สิทธิ์** — ช่างเห็นและแตะได้เฉพาะงานของตัวเอง, ลำดับสถานะบังคับ `แจ้งใหม่ → มอบหมายแล้ว → กำลังซ่อม → เสร็จแล้ว` (ยกเลิกได้ทุกจุดก่อนปิดงาน)

## หลายหอในระบบเดียว

สมัครที่ `/signup` ครั้งเดียวได้ทั้งบัญชีเจ้าของและหอของตัวเอง พร้อมค่าตั้งต้นที่จำเป็น
(รอบบิล อัตราค่าน้ำ-ไฟ ประเภทห้อง ค่าบริการ) แล้วหน้า `/welcome` จะไล่ขั้นตอนที่เหลือให้

การแยกข้อมูลทำสองชั้น

1. **session พก `propertyId`** — ทุกหน้าฝั่งเจ้าของดึงผ่าน `currentPropertyId()` ห้ามใช้ `findFirst` หาหอเด็ดขาด
2. **ทุก action ที่รับ id จากฟอร์มต้องตรวจก่อน** — `src/lib/scope.ts` มีตัวตรวจว่า ห้อง/ตึก/สัญญา/บิล/งานซ่อม
   นั้นอยู่ในหอของผู้ใช้จริง กันการยิง id ข้ามหอเข้ามาแก้ข้อมูล

> token รุ่นก่อนที่ไม่มี `propertyId` ใช้ไม่ได้แล้ว ผู้ใช้เดิมต้องล็อกอินใหม่หนึ่งครั้ง

## เข้าสู่ระบบด้วย LINE (LIFF)

ผู้เช่ากดจากเมนูใน LINE แล้วเข้าได้เลย ไม่ต้องจำรหัส · **เว้นตัวแปรว่างไว้ได้** ระบบจะซ่อนปุ่ม LINE
ให้เองและใช้การล็อกอินด้วยรหัสเข้าใช้งานตามเดิม

**1. สร้างช่องทางใน [LINE Developers Console](https://developers.line.biz/console/)**

New Provider → Create channel → เลือก **LINE Login**

**2. สร้าง LIFF app** — ในช่องทางนั้น แท็บ **LIFF** → Add

| ตั้งค่า | ค่าที่ใช้ |
|---|---|
| Size | `Full` |
| Endpoint URL | `https://<โดเมนของคุณ>/t/line` |
| Scopes | ติ๊ก **openid** และ **profile** (ไม่มี `openid` จะไม่ได้ ID token) |

**3. ใส่ตัวแปร** ทั้งใน `.env` และใน Environment Variables ของ Vercel

| ตัวแปร | เอามาจาก | ความลับ |
|---|---|---|
| `NEXT_PUBLIC_LIFF_ID` | แท็บ LIFF → LIFF ID | ไม่ใช่ (ไปถึงเบราว์เซอร์) |
| `LINE_LOGIN_CHANNEL_ID` | แท็บ Basic settings → Channel ID | ใช้ฝั่งเซิร์ฟเวอร์เท่านั้น |

**ครั้งแรกยังต้องกรอกรหัสเข้าใช้งาน + เบอร์** เพราะ LINE ยืนยันได้แค่ว่า *"คนนี้คือเจ้าของบัญชี LINE นี้"*
แต่บอกไม่ได้ว่าเป็นผู้เช่าห้องไหนของหอไหน · ผูกแล้ว LINE user id จะถูกเก็บใน `User.lineUserId`
ครั้งต่อไปเปิดจาก LINE แล้วเข้าได้เลย

> **ID token ถูกส่งไปให้ LINE ตรวจลายเซ็นเสมอ** (`POST /oauth2/v2.1/verify` พร้อม `client_id`)
> ไม่ได้ถอด JWT อ่านเองแล้วเชื่อ ไม่งั้นใครก็ปลอม token มาสวมเป็นผู้เช่าคนอื่นได้ ·
> บัญชี LINE หนึ่งผูกได้กับผู้เช่าคนเดียว

## ต่อไป

1. แจ้งเตือนผ่าน LINE (บิลออก / งานซ่อมคืบหน้า) — ตาราง `Notification` เตรียมไว้แล้ว ต้องใช้ช่อง Messaging API เพิ่ม
2. แนบรูปงานซ่อม (ตาราง `MaintenancePhoto` เตรียมไว้แล้ว รอที่เก็บไฟล์)
3. PromptPay QR + ตรวจสลิป
4. PDF ฝั่ง server (สำหรับส่งทาง LINE)

## ภาษาสี

กฎเดียวที่ต้องจำ: **ม่วงคราม = สิ่งที่กดได้ · สีอุ่น/สด = สถานะข้อมูล · สีเย็น/จาง = โครงสร้างอาคาร**

สถานะไล่ 5 ขั้นจากเงียบไปดัง ยิ่งดังยิ่งต้องลงมือทำ

| ขั้น | สี | หมายถึง | ตัวอย่าง |
|---|---|---|---|
| 1 | เทาอ่อน | ไม่ใช้งานแล้ว | ฉบับร่าง ยกเลิก สิ้นสุด |
| 2 | เทาเข้ม | กำลังเดินตามปกติ | รอชำระ กำลังซ่อม ปิดปรับปรุง |
| 3 | เขียว | ดีอยู่แล้ว | ชำระแล้ว ปิดงาน มีผู้เช่า |
| 4 | เหลือง | ต้องตามอีกหน่อย | จองแล้ว ชำระบางส่วน ใกล้หมดอายุ |
| 5 | แดง | ต้องทำเดี๋ยวนี้ | เกินกำหนด ค้างชำระ งานด่วน |

### ผังห้อง

แยกสองชั้นด้วย**ความอิ่มสี** — ห้องเป็นสีสดพื้นเต็ม ส่วนโครงสร้างอาคารเป็นสีเย็นพื้นจาง
ตาจึงจับกลุ่มห้องได้ก่อนแล้วค่อยเห็นทางเดิน-บันไดเป็นฉากหลัง

| ช่อง | สี | สัญลักษณ์ |
|---|---|---|
| มีผู้เช่า | เขียวอ่อน | — |
| **ค้างชำระ** | **แดงอ่อน (ทับสถานะอื่นเสมอ)** | ไอคอนธนบัตร |
| ว่าง | ขาว ขอบประ | — |
| จองแล้ว | เหลืองอ่อน | — |
| ปิดปรับปรุง | เทา + ลายทแยง | — |
| มีงานซ่อม | (ทับบนสีสถานะ) | ไอคอนประแจ |
| ทางเดิน | เทาจาง | — |
| บันได / ลิฟต์ | ฟ้าจาง | ไอคอนขั้นบันได / ลูกศรขึ้นลง |
| ห้องน้ำรวม | ฟ้าอมเขียวจาง | ไอคอนอ่างอาบน้ำ |
| ทางเข้า-ออก | ขอบเข้มหนา | ไอคอนประตู |

สีชุดนี้ใช้เหมือนกันทั้ง **ผังห้อง · ตึกและชั้น · รายการห้องในตึก · ตัวจัดผัง** โดยมีแหล่งเดียวคือ `src/lib/room-style.ts`
จึงไม่ต้องจำสองชุดและแก้ที่เดียวเปลี่ยนทั้งระบบ

สีไม่เคยเป็นตัวบอกความหมายเพียงอย่างเดียว ทุกที่ที่ใช้สีต้องมีตัวหนังสือ ไอคอน หรือลวดลายกำกับ
ค่าสีจริงอยู่ใน `src/app/globals.css` และทุกคู่ข้อความ/พื้นผ่าน WCAG AA
